## 2. 项目背景与目标

当前项目中的院校、专业、学费、历史分数和位次主要来自 mock/seed 数据，无法支撑真实的江苏省志愿推荐。

本项目建设一套江苏省招生数据采集流水线，自动发现、下载、解析和更新官方数据，为 SQL 精确查询、规则引擎和 RAG 提供可追溯的真实数据。

MVP 只覆盖江苏省和明确配置的 10 所目标高校，不采集其他高校详情。生产采集由 Python 定时任务执行；Codex 用于分析数据源、编写采集器和解析器、生成测试以及处理网站年度变化。

---

## 3. 范围

### 3.1 目标高校白名单

系统必须使用固定白名单过滤数据，不根据第三方排名动态选择高校。

```yaml
target_universities:
  - university_code: TBD
    name: TBD
```

开发开始前，由产品侧确认 10 所高校的标准名称和教育部院校代码。省考试院文件中涉及其他高校的数据可以保存在原始文件层，但不得解析发布到业务数据库。

### 3.2 P0 结构化数据

#### A. 江苏省招生规则

- 年份、批次、物理类/历史类；
- 志愿填报单位和最大志愿数；
- 平行志愿或顺序志愿；
- 投档规则和同分排序规则；
- 是否允许专业调剂及调剂范围；
- 批次控制分数线；
- 完整一分一段表。

#### B. 当年分省招生计划

最小数据粒度：

```text
年份 + 科类 + 批次 + 院校 + 院校专业组 + 专业
```

关键字段：

- 院校代码、院校名称；
- 专业组代码；
- 专业代码、专业名称；
- 计划人数；
- 学费、学制、校区；
- 选科要求；
- 招生类型：普通、中外合作、专项等；
- 体检、外语、单科等重要限制；
- 来源 URL、原始文件、页码/表格行、数据版本。

#### C. 最近 3 个完整录取年度的数据

- 院校专业组投档最低分、最低位次；
- 专业录取最低分、最低位次；
- 官方提供时保存平均分、最高分和录取人数；
- 明确区分投档线、专业录取线和征集志愿数据；
- 区分普通、中外合作、专项、不同校区等招生类型。

如果高校未公开专业录取数据，记录为缺失，不得使用推算或 mock 值补齐。

#### D. 院校、学院和专业主数据

- 院校标准名称、教育部代码、所在地、办学性质、招生官网；
- 学院名称、所属院校、生效年份；
- 专业国家代码、名称、专业类、学制、学位；
- 专业所属学院、校区；
- 开设、停招或撤销状态。

学院信息只用于专业归属和展示，不作为投档计算维度。

### 3.3 P0 向量库数据

只保存以下可用于语义检索的关键文本：

- 江苏省招生政策关键段落；
- 目标高校招生章程关键段落；
- 目标高校专业介绍；
- 目标高校转专业政策。

招生章程重点抽取录取规则、调剂、选科、体检、外语、单科、学费和中外合作说明。就业报告、完整培养方案和奖助学金政策不在本期范围内。

### 3.4 非目标

- 不采集江苏省之外的省级规则；
- 不采集白名单之外高校的详细数据；
- 不构建全国通用爬虫；
- 不绕过登录、验证码、付费权限或访问限制；
- 不采集考生个人信息；
- 不用 LLM 推测分数、位次、计划数和学费；
- 不在本期建设复杂的数据运营后台，先提供最小审核能力。

## 4. 数据来源与获取方式

| 优先级 | 来源 | 数据 | 首选采集方式 |
|---|---|---|---|
| P0 | 江苏省教育考试院 | 规则、控制线、一分一段、招生计划、投档线 | XLSX/CSV > HTML > PDF |
| P0 | 教育部 | 院校名单、专业标准目录 | 官方附件下载 |
| P0 | 阳光高考 | 招生章程 | HTML 正文或 PDF |
| P1 | 10 所高校招生网 | 分省计划、专业录取线、专业介绍 | HTML/XLSX/PDF |
| P1 | 10 所高校教务处 | 转专业政策 | HTML/PDF |

当招生计划没有公开可下载的数据时，依次采用：高校招生网分省计划、官方合作数据文件、合法授权数据源、人工导入。不得通过规避访问控制的方式采集。

## 5. 功能需求

### 5.1 数据源注册

每个数据源配置：

- 来源名称和入口 URL；
- 数据类型和适用年份；
- 目标高校代码，可为空；
- 采集方式和解析器；
- 更新频率；
- 最近成功时间、checksum、启用状态。

### 5.2 自动采集

- 定时检查列表页和附件变化；
- 下载 HTML、XLSX、CSV、PDF；
- 通过 checksum 跳过未变化内容；
- 支持增量更新、失败重试、超时和告警；
- JavaScript 页面仅在普通 HTTP 无法获取时使用 Playwright；
- 所有原始文件先保存，再进行解析。

### 5.3 解析与标准化

推荐技术：

- HTTP：`httpx`；
- HTML：`BeautifulSoup`/`lxml`；
- Excel：`pandas`/`openpyxl`；
- 文本 PDF：`pdfplumber`；
- 扫描 PDF：PaddleOCR；
- 动态页面：Playwright。

统一标准化院校名称和代码、物理/历史类、批次、专业组、专业代码、招生类型、校区、学费单位、分数和位次。

### 5.4 数据校验

- 必填字段检查；
- 只允许白名单高校进入发布数据；
- 院校和专业代码映射检查；
- 专业组/专业唯一性检查；
- 分数、位次、计划人数合理范围检查；
- 分数与一分一段数据的一致性检查；
- 同一来源重复记录检查；
- 与上一年度的数据量和字段差异检查；
- 冲突和异常数据进入待审核状态，不自动发布。

### 5.5 版本与溯源

每次发布生成不可变版本，例如：

```text
jiangsu_2026_policy_v1
jiangsu_top10_2026_plan_v1
jiangsu_top10_2025_admission_v1
```

每条发布记录必须保存：

- `source_url`；
- `source_document_id`；
- `source_title`；
- `year`；
- `authority_level`；
- `collected_at`；
- `parser_version`；
- `dataset_version`；
- PDF 页码或表格行号。

### 5.6 RAG 入库

```text
原始 HTML/PDF
→ 正文与章节提取
→ 按语义章节切分
→ 添加省份/年份/院校/页码元数据
→ 生成 embedding
→ 写入 pgvector
```

不得继续使用当前的标题占位文本作为文档正文。

## 6. 技术架构

```text
定时任务
  → Source Registry
  → Collectors（HTML / Excel / PDF / Playwright）
  → 原始文件存储
  → Parsers
  → Staging 暂存表
  → Normalizer + Validator
  → 人工审核异常
  → PostgreSQL / pgvector 发布
```

## 7. 项目计划

| 周期 | 工作 | 交付物 |
|---|---|---|
| 第 1 周 | 确认 10 所高校白名单；审计江苏考试院和高校数据入口；冻结字段模型 | 白名单、数据源清单、字段字典、样例文件 |
| 第 2 周 | 建设采集框架、原始文件存储、任务日志；完成省级规则和一分一段采集 | Collector 框架、省级规则数据 |
| 第 3 周 | 完成目标高校当年招生计划、最近三年专业组投档线采集 | 招生计划和投档数据集 |
| 第 4 周 | 完成专业录取、学院专业主数据、章程/专业介绍/转专业政策采集 | 高校结构化数据和 RAG 文档 |
| 第 5 周 | 完成标准化、校验、异常审核、定时任务及现有系统接入 | 发布数据集、自动任务、测试和验收报告 |

页面异构严重或官方数据不可公开下载时，专业录取数据按高校逐个适配，不阻塞已验证的省级数据和招生计划先行发布。

## 8. 验收标准

- 发布数据只包含确认的 10 所高校；
- 当年招生计划公开数据关键字段覆盖率不低于 95%；
- 最近 3 个完整年度的官方专业组投档线完整；
- 官方公开的专业录取数据覆盖率不低于 90%；
- 关键字段人工抽样准确率不低于 99%；
- 数据来源可追溯率 100%；
- 同一任务重复运行不产生重复记录；
- 页面或附件变化可以自动发现并告警；
- 解析异常不会直接污染发布数据；
- 招生章程、专业介绍和转专业政策可以按年份、院校和文档类型检索；
- 缺失数据明确标记，禁止使用 mock 或模型推测值补齐。

## 9. Codex 与 Python 的职责边界

Codex 负责：

- 分析江苏考试院和高校页面结构；
- 编写、测试和修复 Python 采集器；
- 为 PDF、Excel 和 HTML 编写解析规则；
- 生成解析快照测试和异常分析报告；
- 在页面年度改版后协助更新适配器。

Python 服务负责：

- 生产环境定时采集；
- 下载、解析、校验和入库；
- 重试、告警、版本发布；
- 保证任务幂等和数据可追溯。

人工负责：

- 确认目标高校白名单；
- 审核冲突、低置信度和版式异常数据；
- 批准正式数据集发布。
