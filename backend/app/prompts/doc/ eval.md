结论：作为“提示词契约的确定性单元测试”，写得不错；但作为“提示词评测体系”，覆盖还不完整。

我会给：

- 确定性单元测试：7.5/10
- 完整提示词评测：4/10

## 做得好的地方

以下设计值得保留：

- 所有测试纯离线运行，没有真实模型调用。
- Prompt 组合通过 Registry 动态获取，模板覆盖比较全面。
- 同时检查缺失参数和多余参数，比只检查缺参更严格。
- Pydantic 使用 `extra="forbid"`，能够拦住模型输出字段漂移。
- 覆盖了 JSON 围栏、非法 JSON、多余字段、错误字段类型等常见模型输出问题。
- `passed=true` 但携带问题列表会被拒绝，业务不变量设计得很好。
- LLM Judge 解析异常采用 fail-closed。
- 审计写入失败不会拖垮主链路，同时业务异常仍会向上抛出。
- 流式调用要求返回 usage，考虑到了后续可观测性。

## 还缺少真正的“提示词效果评测”

这个文件主要测试的是 Prompt 周边基础设施，不会真的判断 Prompt 写得好不好。例如它无法回答：

- 模型是否遵守禁止过度承诺的要求
- 是否稳定输出正确 JSON
- 是否会被 `$plan_text` 中的注入指令劫持
- 生成的推荐理由是否基于候选数据
- Prompt 新版本比旧版本更好还是更差
- 同一 Prompt 重复运行是否稳定

建议把提示词层分成三套测试：

```text
prompt_layer/
├── test_prompt_contracts.py       # 当前这类确定性测试
├── test_prompt_call_sites.py      # Prompt 与真实调用方的集成契约
└── test_prompt_behavior_evals.py  # 调用真实模型，规则 + LLM Judge
```

其中行为评测至少包含：

- 正常用例
- 信息缺失用例
- 冲突指令用例
- Prompt 注入用例
- 结构化输出稳定性
- 新旧版本成对比较
- 每个用例重复运行 3～5 次

总体上，这份测试是一个很好的第一层，但应该把它准确定位成“Prompt 契约与解析器测试”。下一步最优先补的是：**真实调用点契约、`output_schema` 统一注册，以及独立的 Prompt 行为评测集。**
